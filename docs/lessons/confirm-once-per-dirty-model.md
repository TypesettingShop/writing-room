# 저장 확인의 단위를 공유 변경 상태에 맞춘다

## What happened

- 작품을 닫을 때 텍스트 편집기와 텍스트 커스텀 편집기가 같은 글의 변경을 두 번 물었다. 첫 답을 **Don't Save**로, 두 번째를 **Save**로 고르면 버리기로 한 글이 파일에 써졌다.

## Why

- 각 탭에는 다른 입력이 있지만 두 입력은 변경 상태가 하나인 텍스트 모델을 공유한다. 같은 리소스를 연 커스텀 문서 중에는 확장과 뷰 종류별로 변경 상태가 따로 있는 경우도 있다.

## Do this instead

- 여러 편집기를 닫을 때 입력의 `sharesDirtyState`로 공유 변경을 찾고, 변경 상태마다 한 번 확인한다. 같은 텍스트 모델을 보는 편집기는 답을 공유한다. 커스텀 문서는 같은 모델 인스턴스를 보유하는 입력끼리 답을 공유한다.
- 답을 모두 받은 뒤 저장과 버리기를 실행한다. 회귀 테스트는 먼저 **Don't Save**를 선택하고, 확인이 잘못 한 번 더 뜨면 **Save**를 선택하게 한다. 확인 횟수와 실제 저장된 파일을 함께 검사한다.
