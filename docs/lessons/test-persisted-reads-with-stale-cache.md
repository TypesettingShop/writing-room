# 영속 스냅숏을 읽는 테스트는 탭 캐시와 영속 값을 다르게 둔다

## What happened

- 확장 상태 저장 리뷰 wr-s9ew.hy2의 발견 4. 영속 모드의 설치 세대 확인과 2 MiB 합계 검사를 탭 캐시로 바꾸어도 기존 단위 테스트가 통과했다.
- 다른 탭의 쓰기를 저장소에 직접 흉내 내고, 해당 탭에는 저장 이벤트를 보내지 않는 테스트를 더했다. 설치 목록이 달라진 경우와 두 범위의 상태 합계가 달라진 경우를 각각 확인했다.

## Why

- 한 서비스를 통해 값을 준비하면 영속 스냅숏과 그 탭의 캐시가 함께 바뀐다. 두 곳이 같은 값을 답하는 테스트로는 어느 곳에서 읽는지 확인할 수 없다.

## Do this instead

- 쓰기 전 다른 탭이 값을 바꿀 수 있다면 테스트에서 백엔드만 갱신한다. 검사해야 할 조건은 백엔드와 탭 캐시에서 각각 다른 결론이 나오게 정한다.
- 정상 쓰기 경로를 호출한 뒤, 읽기 원천을 탭 캐시로 바꾸면 테스트가 실패하는지 확인한다.
