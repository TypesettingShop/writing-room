# 같은 이름으로 명령을 등록할 때는 기존 호출 경로를 함께 지킨다

## What happened

- 선택 서식 단축키를 잇기 위해 editor.action.formatSelection을 워크벤치 시작 중 등록했다. 뒤에 시작한 DocumentApiCommands는 이미 있는 명령의 브리지를 등록하지 않았다.
- 키보드 테스트는 통과했다. 리뷰 wr-c9d8.ogv에서 확장 호출이 활성 페인 폴백과 호출 인자, 에디터가 없을 때의 오류를 잃었음을 확인했다.

## Why

- 같은 명령 이름은 키바인딩과 확장 API에서 함께 쓴다. 등록 시점이 달라지면 기존 호출자가 새 핸들러로 들어올 수 있다.

## Do this instead

- 명령을 새로 등록하기 전에 같은 id를 등록하고 호출하는 곳을 찾는다. 기존 핸들러가 제공하는 포커스 폴백, 인자 전달과 실패 동작을 보존한다.
- 키 입력과 API 호출 양쪽을 확인한다. 포커스가 없고 활성 페인이 있는 경우처럼 두 진입점의 전제가 다른 상태를 테스트에 둔다.
