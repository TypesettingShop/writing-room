# 새 요청을 받기 전에 대기 용량을 확인한다

## What happened

- 로그인에서는 동시에 실행하는 비밀번호 해시 수를 제한했지만 대기 중인 작업 수에는 상한이 없었다. Google 로그인에서는 대기 중인 state의 상한을 지키면서 아직 사용 중인 state를 지울 수 있었다.

## Why

- 처리량 제한은 큐에 남길 작업 수를 정하지 않는다. 이미 발급한 state는 브라우저 콜백이 돌아올 때까지 유효해야 한다.

## Do this instead

- 요청을 큐에 추가하거나 state를 발급하기 전에 용량을 확인한다. 가득 차면 새 요청에 재시도 시점을 보내고, 유효한 대기 항목은 완료하거나 만료될 때까지 유지한다.
- 시간과 용량 경계를 테스트한다. 한도를 넘은 요청이 빠르게 끝나는지, 앞서 받은 요청이 끝난 뒤 새 작업을 받아들이는지 확인한다.
