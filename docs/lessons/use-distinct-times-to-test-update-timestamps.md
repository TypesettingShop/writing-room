# 수정 시각 테스트에서는 생성과 쓰기의 시각을 구분한다

## What happened

- 작품 템플릿을 저장할 때 작품의 수정 시각을 갱신해야 했다. 테스트에서는 작품 생성과 템플릿 저장의 시계가 같은 시각을 반환해서 갱신을 빠뜨려도 통과했다.

## Why

- 쓰기 전후에 기대하는 시각이 같으면 저장 결과로 갱신 실행 여부를 구분할 수 없다.

## Do this instead

- 생성과 성공한 쓰기에 서로 다른 시각을 주고 각 단계에서 다시 읽은 수정 시각을 확인한다.
- 충돌이나 검증 실패를 확인할 때는 시계를 한 번 더 진행시켜 마지막 성공 시각이 보존되는지 단언한다. 갱신 호출을 빼면 성공 경로의 테스트가 실패해야 한다.
