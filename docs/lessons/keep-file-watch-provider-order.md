# 이름 바꾸기 감시는 제공자의 변경 순서로 시험한다

## What happened

- IndexedDB에서 이름을 바꾸면 새 경로의 생성과 이전 경로의 삭제가
  전달된다. 첫 브라우저 테스트는 삭제가 먼저 도착한다고 가정했다.

## Why

- 파일 작업 이벤트는 한 번의 이름 바꾸기를 나타낸다. 파일 감시 이벤트는
  제공자가 보고한 경로별 변경을 나타낸다. IndexedDB 제공자는 새 경로를
  기록한 뒤 이전 경로를 지우고 그 순서로 변경을 보고한다.

## Do this instead

- 파일 감시의 묶음 전달은 제공자가 낸 순서대로 모두 도착하는지 검사한다.
  이름 바꾸기 작업의 경계는 `onWillRenameFiles`와 `onDidRenameFiles`에서
  각각 확인한다.
