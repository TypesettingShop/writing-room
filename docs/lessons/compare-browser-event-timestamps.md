# 브라우저 이벤트 간격은 이벤트에 기록된 시각으로 잰다

## What happened

- 시각 Markdown 편집기의 IME 리셋 복원은 빈 조합 종료와 뒤이은 포인터·포커스 이벤트가 가까이 발생했는지 확인한다. 처음에는 두 핸들러가 실행된 순간을 비교해 사용자 입력이 이어졌어도 복원을 건너뛸 수 있었다.

## Why

- 브라우저는 이벤트 전달 사이에 레이아웃이나 렌더링을 할 수 있다. Chromium에서는 클릭이 IME 리셋을 일으키고 포인터 이벤트는 나중에 도착하므로, 타임스탬프 순서와 전달 순서가 다를 수도 있다.

## Do this instead

- 한 문서에서 발생한 브라우저 이벤트끼리 연관 지을 때는 각 이벤트의 `timeStamp`를 비교한다. 이벤트를 만든 시각과 전달한 시각을 따로 제어하는 테스트로, 늦게 전달된 이벤트와 실제로 시간 창을 넘긴 이벤트를 각각 확인한다.
