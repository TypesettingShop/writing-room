# 포인터로 옮긴 Markdown 선택은 트랜잭션에 표시한다

## What happened

- 읽기 전용 WYSIWYG에서 타자기 스크롤을 켜고 다른 줄을 오른쪽 클릭하면, 커서가 옮겨진 뒤 화면까지 움직여 방금 연 문맥 메뉴가 닫혔다.

## Why

- 네이티브 DOM 선택만 옮기면 ProseMirror가 다음 `selectionchange`에서 그 변경을 트랜잭션으로 받아들인다. 포인터 표시가 없으면 타자기 스크롤이 커서 줄을 가운데로 옮기고, 편집면의 스크롤 이벤트가 열린 메뉴를 닫는다.

## Do this instead

- 포인터 입력 때문에 선택이 바뀌면 메뉴 위치를 정하기 전에 `setMeta('pointer', true)`가 달린 선택 트랜잭션을 전달한다. 읽기 전용에서는 먼저 DOM 선택을 편집면 안에 둔다.
- 회귀 테스트에서는 타자기 스크롤 활성화와 클릭한 줄의 선택을 확인한다. 브라우저가 선택 변경과 스크롤을 처리한 뒤에도 이전 스크롤 위치와 메뉴가 유지되는지 검사한다.
