# 포인터로 옮긴 Markdown 선택은 트랜잭션에 표시한다

## What happened

- 읽기 전용 WYSIWYG에서 타자기 스크롤을 켠 채 다른 줄을 오른쪽 클릭했다.
  커서가 옮겨진 뒤 편집면이 스크롤되면서 방금 연 문맥 메뉴가 닫혔다.

## Why

- 네이티브 DOM 선택만 옮기면 ProseMirror는 다음 `selectionchange`에서 그
  변경을 선택 트랜잭션으로 받아들인다. 이 트랜잭션에 포인터 표시가 없으면
  타자기 스크롤이 커서가 있는 줄을 편집면의 세로 가운데로 옮긴다. 이때
  편집면의 스크롤 이벤트가 열려 있던 메뉴를 닫는다.

## Do this instead

- 포인터 입력으로 선택이 바뀌면 메뉴 위치를 정하기 전에
  `setMeta('pointer', true)`를 붙인 선택 트랜잭션을 전달한다. 읽기 전용에서는
  먼저 DOM 선택을 편집면 안에 둔다.
- 회귀 테스트에서는 타자기 스크롤이 켜졌는지, 커서가 클릭한 줄에 놓였는지
  확인한다. 브라우저가 선택 변경과 스크롤을 처리한 뒤에도 이전 스크롤 위치와
  메뉴가 유지되는지 검사한다.
