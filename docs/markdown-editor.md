# 마크다운 파일의 저장 형식

마크다운 원문은 파일에 그대로 저장된다. 편집 모델은 CommonMark 본문, GFM 표·작업
목록·취소선, 각주와 클래스 속성을 읽는다. 원시 HTML은 본문의 문자로 읽는다.

화면 이름은 Manuscript Editor(원고 편집기)다. **Reopen Editor With...** 목록에 이 이름으로 보인다.

## 편집 모드와 실행 취소

- `.md`와 `.markdown`의 기본 모드는 WYSIWYG다. 같은 탭의 제목 툴바, **Markdown: Toggle Source Mode**, **Ctrl+Shift+M**(macOS는 **Cmd+Shift+M**)으로 원문 모드와 오간다. 기본 모드 설정과 저장 방법은 시작 가이드에 있다. [마크다운 편집하기](getting-started.md#마크다운-편집하기)
- 두 모드는 `TextFileEditorModel`을 공유한다. WYSIWYG 문서 변경은 매 트랜잭션에서 직렬화하고 달라진 범위만 모델에 적용한다. 원문 탭이나 확장이 모델을 고치면 WYSIWYG도 새 텍스트를 읽는다.
- WYSIWYG는 이어서 입력한 글자를 500ms 간격으로 묶는다. 서식 명령과 외부에서 들어온 모델 변경은 각각 별도 실행 취소 단계다. 키보드와 **Edit → Undo/Redo**가 같은 이력을 사용하며, 저장한 텍스트로 돌아오면 dirty 표시가 사라진다.
- 원문 탭이나 확장, 다른 창에서 파일을 고치면 Enter로 만들었거나 글을 모두 지운 문단처럼 원문에 기록되지 않은 빈 문단은 WYSIWYG 화면에서 사라진다. WYSIWYG에서 그 외부 변경을 실행 취소하면 빈 문단이 다시 나타난다. 원문 탭에서 변경을 되돌려도 빈 문단은 돌아오지 않는다.
- 모드를 전환한 순간의 마크다운이 새 이력의 시작점이 된다. 그 뒤 첫 편집을 실행 취소하면 전환 순간의 텍스트로 돌아온다. 원문 모드로 전환할 때 같은 파일을 보여 주는 Monaco 창도 새 이력의 시작점을 공유한다. 새로고침은 탭 모드와 초안을 복원한다.
- 이미지의 상대 경로는 문서 폴더를 기준으로 읽는다. 작업 폴더 안의 이미지는 파일 서비스로 읽어 보여 주고, 작업 폴더 밖의 경로나 지원하지 않는 형식은 대체 텍스트와 사유를 보여 준다. HTTPS 이미지는 이미지마다 **Load image** 버튼을 눌러야 요청하며 referrer를 보내지 않는다. HTTP 이미지는 요청하지 않고 대체 텍스트를 보여 준다. 어느 경우든 저장할 때 원래 주소를 유지한다.

## 복사 형식

- WYSIWYG에서 영역을 선택하고 문맥 메뉴의 **Copy** 아래에 있는 **Copy as Markdown**이나 **Copy as HTML**을 고른다. 커맨드 팔레트의 **Markdown** 카테고리에서도 실행할 수 있다. 두 명령의 기본 단축키는 없다.
- **Copy as Markdown**은 보통 **Copy**와 같은 Markdown 원문을 `text/plain`으로 복사한다. 두 형식 복사 명령 가운데 이 명령만 브라우저 탭의 마지막 복사 기록을 갱신한다. 같은 브라우저 탭에서 메뉴의 **Paste as Plain Text**를 사용하면 이 기록을 바탕으로 코드 블록 안에서도 화면에 보였던 글자를 붙여넣는다.
- **Copy as HTML**은 렌더링된 조각을 `text/html`로, 같은 HTML 소스를 `text/plain`으로 담는다. 정렬, 밑줄, 크기와 글꼴 클래스는 `class` 속성에 담긴다. 표에서 본문 셀만 선택하면 머리글 없는 표로 복사한다.
- 상대 이미지 주소는 문서에 적힌 값으로 내보내므로, 다른 앱에서 같은 경로를 찾지 못하면 이미지가 보이지 않을 수 있다.
- 읽기 전용에서는 문맥 메뉴의 항목이 브라우저에 표시된 선택에 따라 활성화된다. 커맨드는 팔레트가 포커스를 가져간 뒤에도 편집기가 기억한 선택을 복사한다.

## 서식 없이 붙여넣기

- 같은 브라우저 탭의 WYSIWYG에서 **Copy**·**Cut**·**Copy as Markdown**으로
  클립보드에 담은 조각을 **Paste as Plain Text**로 보이는 글자만 붙일 수 있다.
  코드 블록 밖에서는 브라우저의 서식 없는 붙여넣기 단축키로도 보이는 글자만 붙일 수 있다.
  문단과 목록 항목 사이는 줄바꿈으로 잇고 표는 칸마다 한 줄로 붙인다.
  이미지는 대체 텍스트로 붙이며 대체 텍스트가 없으면 생략한다. 일반 **Copy**는
  Markdown 원문과 렌더링된 HTML을 함께 담는다.
- 메뉴는 WYSIWYG에서 복사한 HTML 조각이 있으면 화면에 보였던 글자를 복사 기록과
  비교하지 않고 바로 붙인다. 조각이 없으면 클립보드의 일반 텍스트를 이 브라우저
  탭의 마지막 복사 기록과 비교한다.
  메뉴는 이 비교를 코드 블록 안에서도 한다. 기록과 일치하지 않는 일반 텍스트는
  그대로 붙인다.
- 선택한 글을 끌어 옮기거나 도중에 취소해도 마지막 복사 기록은 유지된다.
  기록은 **Copy**·**Cut**·**Copy as Markdown**으로 클립보드에 담을 때만 갱신된다.
- 다른 브라우저 탭이나 창에서 가져온 글 또는 코드 블록에 넣을 글은 일반
  **Copy**로 복사한 뒤 메뉴의 **Paste as Plain Text**를 사용한다. 단축키로는
  Markdown 원문이 들어갈 수 있다. 코드 블록에서 단축키를 쓰면 편집기는 받은
  일반 텍스트를 그대로 넣는다. **Copy as Markdown** 복사본은 이 경우 Markdown
  원문으로 들어간다.
- 단축키가 새로고침 뒤에도 동작하도록 마지막 복사본의 Markdown과 보이는 글자를 이 브라우저 탭의 세션 저장소에 둔다. 탭 세션이 끝나면 사라지며, 저장할 데이터가 1 MiB를 넘으면 새로고침 전까지만 메모리에 둔다.
- 서식 없는 붙여넣기 단축키는 브라우저 기본 동작을 따른다. Chromium에서는 **Ctrl+Shift+V**(macOS는 **Cmd+Shift+V**), macOS Safari에서는 **⌥⇧⌘V**를 사용한다.

## 본문 폭과 배치

- `markdownEditor.contentWidth`는 가운데 배치에서 본문 글줄의 최대 폭을
  지정한다. 좌우 안쪽 여백(패딩)과 경계선을 제외한 폭이다. 단위는 `ch`다.
  기본값 `80`은 편집기 기본 글꼴에서 숫자 `0`의 폭을 80배 한 길이다.
  20–400 사이의 정수를 설정할 수 있으며, 창이 좁으면 표시 영역에 맞춰
  자동으로 줄어든다.
- `markdownEditor.contentLayout`은 `center`(기본값)에서 본문을 가운데에
  배치한다. `fill`은 편집기 전체 폭을 채우며 툴바의 폭 입력칸을
  비활성화한다. 집중 모드의 폭은 `markdownEditor.focusMode.width`로
  설정한다.
- 툴바에서 변경한 폭과 배치는 사용자 설정에 저장되며 열려 있는 모든 WYSIWYG
  편집기에 적용된다. 문서 서식은 아래의 Markdown 클래스로 저장된다.

## 기본 크기와 서체

WYSIWYG 본문은 기본적으로 12 pt와 Noto Sans KR로 표시된다. 사용자
`settings.json`에서 `markdownEditor.fontSize`에 **Size** 목록의 숫자 값을,
`markdownEditor.fontFamily`에 **Font** 목록의 서체 식별자를 입력한다. 예를
들어 `"markdownEditor.fontSize": 11`, `"markdownEditor.fontFamily": "noto-serif-kr"`를
저장하면 열려 있는 WYSIWYG 편집기에도 적용된다.

| 본문 | 제목 1 | 제목 2 | 제목 3 | 제목 4 | 제목 5 | 제목 6 | 부제목 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 12 pt | 24 pt | 18 pt | 14 pt | 12 pt | 10 pt | 9 pt | 16 pt |

본문 기본 크기를 바꾸면 표의 각 제목 크기에 새 본문 크기를 곱하고 12로
나눈 값을 **Size** 목록에서 가장 가까운 값으로 반올림한다. 두 값의 거리가
같으면 큰 값을 쓴다. 계산값이 목록 범위를 벗어나면 최솟값 8 pt 또는 최댓값
72 pt를 쓴다. 예를 들어 본문이 14 pt이면 제목 6의 계산값 10.5 pt는 11 pt로
표시된다. 본문이 8 pt일 때 제목 6은 8 pt, 본문이 72 pt일 때 제목 1은
72 pt로 표시된다. 부제목은 보통 굵기(400)와 부제목 색을 쓴다.
제목과 부제목의 기본 크기는 인용문이나 목록 항목에 붙은 크기 클래스를 따르지
않는다.

서체 식별자는 `noto-sans-kr`, `noto-serif-kr`, `nanum-myeongjo`,
`nanum-gothic`, `monospace`다. 네 한글 서체는 앱에서 제공한다. WYSIWYG
편집기를 처음 열면 서체 스타일시트를 가져오고, 브라우저가 글자에 맞는
서체 조각을 요청한다. 인라인 코드는 고정폭 서체로 표시되며, 그 안에서도
**Font**는 문단이나 인라인 범위에 적용된 서체를 표시한다. 등록된 식별자가 아닌
문자열을 입력하면 본문은 Noto Sans KR을 쓴다. 기존 `serif`·`sans`
객체를 쓰는 설정은 `.font-serif`와 `.font-sans`에 해당 글꼴 목록을
적용하고, 본문은 Noto Sans KR을 쓴다.

## 클래스 속성

문단이나 제목을 꾸미려면 마지막 줄에 클래스 목록을 붙인다. 인용문과 목록 항목의
텍스트에 붙이면 인용문이나 항목에 적용된다. 표에서는 셀별로 붙인다. 글자 일부를
꾸미려면 대괄호 바로 뒤에 클래스 목록을 쓴다.

```markdown
# 제목 {.center}

부제목 {.subtitle}

> 인용 {.right}

- 항목 {.size-12pt}

| 셀 {.center} |
| --- |

[글자 일부]{.size-18pt .font-noto-serif-kr}
```

- **Size** 목록의 값은 8·9·10·11·12·14·16·18·20·24·28·36·48·72 pt다.
  다른 크기를 고르면 `{.size-18pt}`처럼 절대 크기 클래스를 저장한다.
  기존 `.size-sm`·`.size-lg`·`.size-xl`은 블록 기본 크기에 비례하며
  **Size**에 **Custom**으로 표시된다.
- **Font**에서 다른 서체를 고르면 `.font-noto-sans-kr`,
  `.font-noto-serif-kr`, `.font-nanum-myeongjo`, `.font-nanum-gothic`,
  `.font-monospace` 중 해당 클래스를 저장한다. 기존 `.font-serif`와
  `.font-sans`는 **Serif**와 **Sans Serif**로 표시된다. 기존 `.font-mono`도
  고정폭 서체로 표시된다.
- **Size**와 **Font**는 적용된 값을 목록에서 체크한다. 블록 전체에 원래
  적용될 값을 고르면 그 블록의 해당 서식 클래스를 지운다. 텍스트 일부에서
  블록의 값을 고르면 그 범위의 인라인 클래스를 지운다. 기본 크기와 서체는
  보는 사람의 설정이므로 클래스를 지울지는 그 설정에서 시작한 상속값과
  비교해 결정한다. 기존 키바인딩에서 `markdownEditor.setFontSize`나
  `markdownEditor.setFontFamily`에 넘기던
  `'default'` 인자도 해당 범위의 클래스를 지운다. 그 범위에는 블록이나 상위
  블록의 값, 둘 다 없으면 설정의 기본값이 적용된다.
- 정렬 버튼은 문단에 적용된 정렬을 표시한다. 문단에 정렬 클래스가 없으면
  정렬이 지정된 가장 가까운 상위 블록(인용문, 목록 항목 등)의 값을 상속하며,
  기본값은 왼쪽이다. 상속받은 값과 같은 버튼을 누르면 문단에 이미 붙은 정렬
  클래스를 지운다. 다른 정렬을 고르면 문단에 클래스를 저장한다. 예를 들어
  `{.center}` 인용문 안에서 **Align Left**는 문단에 `{.left}`를 저장하고,
  **Align Center**를 누르면 그 클래스를 지워 가운데 정렬을 상속한다. 기존
  `.justify`는 그대로 읽고 저장하며 양쪽 정렬로 표시한다. 해당 블록에서는
  세 정렬 버튼이 모두 눌리지 않은 상태로 표시된다.
- 클래스 이름은 소문자로 시작하고 뒤에 소문자, 숫자, 하이픈을 쓸 수 있다. 여러
  클래스는 공백으로 나눈다. 사용자 클래스와 입력 순서가 저장된다.
- 줄 끝의 클래스 목록 앞에는 공백을 둔다. `글자{.class}`나 `![그림](a.png){.class}`처럼
  붙여 쓰면 글자로 읽는다.
- 밑줄을 적용한 글은 `[글]{.underline}`으로 저장한다. 굵게나 링크, 크기·서체
  클래스와 함께 쓸 수 있다. 클래스 속성 문법을 지원하지 않는 Markdown
  렌더러에서는 표기가 글자로 보일 수 있다. 다른 앱에서 HTML을 붙여넣을 때
  CSS 밑줄은 링크 밖의 글에 적용된다.
- 클래스 목록만 있는 문단은 빈 줄 뒤에 있어도 바로 앞 블록(문단, 제목, 인용문, 목록,
  표, 코드 블록, 구분선, 각주)에 붙는다. 앞 블록이 없으면 글자로 남는다. 여러 블록을
  담은 인용문, 목록, 표, 코드 블록, 구분선은 이렇게 꾸민다. 클래스처럼 보이는 글자만
  있는 문단을 쓰려면 `\{`로 시작한다. 인용문이나 목록 항목 안의 문단만 꾸밀 때는
  같은 문단의 다음 줄에 `{.class}`를 쓰고 그 줄에도 인용 기호나 목록 들여쓰기를 넣는다.
  목록 항목 안에서 본문과 클래스 줄 사이를 한 줄 비워도 클래스는 문단에 붙으며,
  그 빈 줄은 목록 항목 사이를 비운 것과 같이 목록을 느슨하게 만든다.
- 목록 항목과 인용문 안의 클래스가 붙은 빈 문단은 `[]{.class}`로 쓴다.
  `- []{.class} {.item}`에서 `class`는 빈 문단에, `item`은 목록 항목에 붙는다.
  인용문에서는 `> []{.class}`를 한 문단으로 쓰고, 인용문 자체의 클래스는 인용문
  바깥의 클래스 전용 줄에 쓴다.
- 기존 문서의 `- []{.x}`와 `> []{.x}`도 클래스가 붙은 빈 문단으로 읽힌다.
  이 위치에서 `[]{.x}`를 글자로 쓰려면 `\[\]\{.x}`로 이스케이프한다.
  최상위의 `[]{.x}`는 글자로 읽힌다.
- 중괄호를 글자로 쓰려면 `\{`로 이스케이프한다. 코드 안의 중괄호와 링크·이미지의
  주소 및 제목은 해당 콘텐츠에 속한다. 이미지 설명은 평문으로 읽는다.

## 정규화 규칙

읽은 문서의 최상위 블록을 편집하지 않으면 원래 표기와 줄 끝을 그대로 저장한다.
편집 때문에 블록 경계가 바뀌면 빈 줄을 다시 쓸 수 있다. 링크 정의가 바뀌어 기존
링크가 다른 곳을 가리킬 수 있으면 기존 대상 URL을 인라인으로 저장한다.

| 다시 쓰는 부분 | 저장 표기 |
| --- | --- |
| 제목 | 한 줄 밑줄 제목은 `#` 또는 `##`로 쓴다. 여러 줄 밑줄 제목은 줄바꿈과 레벨을 유지하고, 마지막 텍스트 줄 아래에 `===` 또는 `---`를 쓴다. 제목 클래스는 마지막 텍스트 줄에 붙인다. 밑줄 제목은 빈 줄에서 끝나므로 제목 앞뒤의 줄바꿈은 지우고 이어진 줄바꿈은 하나로 쓴다. 3~6단계 제목은 한 줄로만 쓸 수 있어 줄바꿈을 공백으로 쓴다. |
| 줄바꿈과 공백 | 공백 두 칸으로 쓴 강제 줄바꿈은 줄 끝의 `\`로 쓴다. 본문의 일반 줄바꿈은 줄바꿈으로 남긴다. 줄 양끝에 필요한 공백과 탭은 문자 참조로 쓴다. |
| 목록 | 글머리 기호와 번호 목록의 시작 번호·구분 기호를 유지한다. 이후 번호는 1씩 올린다. 첫 문단에 내용이 있는 항목 아래에서는 하위 목록을 새 줄에 4칸 이상 들여쓴다. `100. `처럼 기호와 뒤 공백이 더 길면 그 너비를 쓴다. 후속 문단과 코드 블록, 첫 문단이 비어 있는 항목의 하위 목록은 기호와 뒤 공백의 너비를 따른다. 같은 기호를 쓰는 목록 둘이 새로 붙으면 둘째 기호를 바꿔 두 목록을 유지한다. 작업 목록은 `[x]`와 `[ ]`로 쓴다. |
| 강조와 코드 | `*`, `_`, `**`, `__`와 코드 구분자의 표기를 유지한다. 편집한 내용과 구분자가 충돌하거나 밑줄 강조가 단어 속에 들어가면 구분자를 조정한다. 들여쓴 코드는 펜스로 바꾼다. 펜스 정보 앞뒤 공백을 정리한다. |
| 표 | 파이프를 열 구분자로 쓰고 셀 안의 파이프는 `\|`로 이스케이프한다. 첫 행은 머리글이다. 머리글의 각 열 정렬에 따라 `:---`, `:---:`, `---:`를 쓴다. 편집 중에 행의 열 수가 달라지면 짧은 행의 끝에 빈 셀을 채운다. HTML 표를 붙여넣으면 원래 셀마다 GFM 셀 하나를 만들고 행·열 병합 속성은 버린다. |
| 클래스 | 클래스 사이 공백을 한 칸으로 쓴다. 클래스가 있는 인용문이나 여러 블록을 감싼 컨테이너에는 클래스 전용 줄을 쓸 수 있다. 목록 항목과 인용문 안의 클래스가 붙은 빈 문단은 `[]{.class}`로 쓴다. 느슨한 목록에 항목과 문단이 하나씩 있으면 문단과 클래스 전용 줄 사이에 빈 줄을 둔다. `- - 항목`처럼 상위 항목의 기호 줄에서 시작한 목록에도 적용한다. 이 문단이 비어 있으면 `[]{}`를 쓰고 한 줄을 비운 뒤 후속 줄의 들여쓰기로 클래스 전용 줄을 쓴다. |
| 링크와 일반 문자 | 편집된 블록에서 참조 링크를 인라인 링크로 쓴다. 참조 정의는 별도 블록으로 남긴다. 일반 문자가 Markdown 구문으로 다시 읽히지 않도록 이스케이프를 추가할 수 있다. |
| 파일 경계 | 새 블록을 잇는 기본 구분은 빈 줄이다. 새 문서는 LF로 쓴다. 읽어 온 파일을 편집할 때는 그 파일의 첫 줄바꿈 형식을 새로 쓰는 부분에 사용한다. |

표의 일부 셀을 범위로 복사하면 클립보드의 `text/html`에는 표 구조가, `text/plain`에는 셀의 텍스트가 담긴다.

### 목록 안의 블록 경계

- 촘촘한 목록의 문단 뒤에는 `#` 제목, 구분선, 표, 코드 펜스, 인용문을
  빈 줄 없이 잇는다. 인용문 뒤의 문단이나 표가 인용에 이어 읽힐 수 있으면
  빈 `>` 줄로 인용을 닫는다. 느슨한 목록의 블록 사이에는 빈 줄을 둔다.
- 촘촘한 항목에서 문단이나 클래스 전용 줄 뒤에 대시 구분선이 오면
  `- - -`처럼 대시 사이를 띄워 밑줄 제목과 구분한다. 항목의 첫 구분선이
  `- ---`나 `* ***`처럼 글머리 기호까지 구분선으로 읽히는 경우에는
  글머리 기호를 먼저 쓰고 구분선을 들여쓴 다음 줄에 둔다. 중첩된
  `-`나 `*` 기호만 모여 구분선으로 읽힐 때도 기호 줄을 나눈다.
- 중첩 목록 뒤 표, 별도 클래스 줄이 필요한 표, 클래스 전용 줄 뒤의 문단이나
  1 이외에서 시작하는 번호 목록에는 블록과 클래스의 소유권을 지키기 위해
  빈 줄을 둔다. 문단이나 클래스 줄 뒤에 오는 하위 목록이 기호만 있는 줄로
  시작할 때도 빈 줄을 둔다. 저장한 마크다운을 다시 읽을 때, 이렇게 넣은 빈 줄이
  같은 항목 안의 블록을 나누면 그 항목을 담은 목록이 느슨해질 수 있다.
- 여러 줄 밑줄 제목이 바로 앞 블록에 이어 읽힐 수 있으면 제목 앞에도 빈 줄을
  둔다. 제목과 이웃 블록이 각각 남도록 하는 구분이다.

## 파이프라인 사용

- `src/editor/common/markdown/markdownIt.ts`의 `createMarkdownIt`는 순서가 있는
  플러그인 목록으로 토크나이저를 만든다.
- `parseMarkdown`은 ProseMirror 문서를 반환한다. `parseMarkdownWithSource`는
  원문 모드와 커서 위치를 맞출 수 있도록 최상위 블록마다 ProseMirror 위치와 줄
  범위, UTF-16 오프셋을 반환한다. 범위 끝은 배타적이다.
- `serializeMarkdown`은 원본에서 읽은 문서의 최상위 블록을 추적한다. 새 문서나
  ProseMirror JSON에서 만든 문서는 위 규칙으로 직렬화한다. 원문 보존은
  ProseMirror 트랜잭션을 거친 문서에도 적용된다.
- 목록 직렬화는 `prosemirror-markdown` 1.13.4의 비공개 상태 `closed`,
  `delim`, `inTightList`와 메서드 `flushClose`, `atBlank`에 의존한다. 버전을 올릴 때
  내부 동작을 확인하고 `src/editor/test/common/markdown/serializer.test.ts`를
  실행한다.
- 등록된 플러그인이 스키마에 없는 토큰을 만들면 해당 최상위 블록을
  `raw_block`에 원문 그대로 보관한다. 이때 필요한 토큰의 `map`은 원문 줄 범위다.
  각주와 링크 정의는 참조되지 않아도 읽고 저장한다.

### 저장 왕복 검사

기본 `npm test`는 조합에서 고른 고정 표본과 최소 재현을 검사한다. 목록
기호와 경계, 형제 항목, 중첩, 인용문, 각주가 포함된 전체 조합을 확인하려면
다음 명령을 실행한다.

```sh
MARKDOWN_ROUNDTRIP_FULL=1 npm test -- src/editor/test/common/markdown/roundtrip.property.test.ts --disableConsoleIntercept
```

테스트는 무편집 원문, 정규화, 텍스트 편집 저장, 클래스 편집 저장을 검사한다.
전체 실행은 검사한 입력 수와 저장 경로별 정규화 횟수를 출력한다.
들여쓴 코드의 펜스 표기와 클래스 경계를 지키기 위해 촘촘한 목록이 느슨해지는
경우만 모델 속성 차이로 허용한다. 문서 트리와 클래스 순서, 인라인 서식과
텍스트가 유지되는지 확인하고, 다시 정규화한 출력이 같은 표기로 계속 저장되는지
검사한다.
