# 마크다운 파일의 저장 형식

마크다운 원문은 파일에 그대로 저장된다. 편집 모델은 CommonMark 본문, GFM 표·작업
목록·취소선, 각주와 클래스 속성을 읽는다. 원시 HTML은 본문의 문자로 읽는다.

## 클래스 속성

문단이나 제목을 꾸미려면 마지막 줄에 클래스 목록을 붙인다. 인용문과 목록 항목의
텍스트에 붙이면 인용문이나 항목에 적용된다. 표에서는 셀별로 붙인다. 글자 일부를
꾸미려면 대괄호 바로 뒤에 클래스 목록을 쓴다.

```markdown
# 제목 {.center}

부제목 {.subtitle}

> 인용 {.right}

- 항목 {.size-lg}

| 셀 {.center} |
| --- |

[글자 일부]{.size-lg .font-serif}
```

- 클래스 이름은 소문자로 시작하고 뒤에 소문자, 숫자, 하이픈을 쓸 수 있다. 여러
  클래스는 공백으로 나눈다. 사용자 클래스와 입력 순서가 저장된다.
- 줄 끝의 클래스 목록 앞에는 공백을 둔다. `글자{.class}`나 `![그림](a.png){.class}`처럼
  붙여 쓰면 글자로 읽는다.
- 클래스 목록만 있는 문단은 빈 줄 뒤에 있어도 바로 앞 블록(문단, 제목, 인용문, 목록,
  표, 코드 블록, 구분선, 각주)에 붙는다. 앞 블록이 없으면 글자로 남는다. 여러 블록을
  담은 인용문, 목록, 표, 코드 블록, 구분선은 이렇게 꾸민다. 클래스처럼 보이는 글자만
  있는 문단을 쓰려면 `\{`로 시작한다. 인용문이나 목록 항목 안의 문단만 꾸밀 때는
  같은 문단의 다음 줄에 `{.class}`를 쓰고 그 줄에도 인용 기호나 목록 들여쓰기를 넣는다.
  목록 항목 안에서 본문과 클래스 줄 사이를 한 줄 비워도 클래스는 문단에 붙으며,
  그 빈 줄은 목록 항목 사이를 비운 것과 같이 목록을 느슨하게 만든다.
- 중괄호를 글자로 쓰려면 `\{`로 이스케이프한다. 코드 안의 중괄호와 링크·이미지의
  주소 및 제목은 해당 콘텐츠에 속한다. 이미지 설명은 평문으로 읽는다.

## 정규화 규칙

읽은 문서의 최상위 블록을 편집하지 않으면 원래 표기와 줄 끝을 그대로 저장한다.
편집 때문에 블록 경계가 바뀌면 빈 줄을 다시 쓸 수 있다. 링크 정의가 바뀌어 기존
링크가 다른 곳을 가리킬 수 있으면 기존 대상 URL을 인라인으로 저장한다.

| 다시 쓰는 부분 | 저장 표기 |
| --- | --- |
| 제목 | 밑줄 제목은 `#` 또는 `##`로 쓴다. |
| 줄바꿈과 공백 | 공백 두 칸으로 쓴 강제 줄바꿈은 줄 끝의 `\`로 쓴다. 본문의 일반 줄바꿈은 줄바꿈으로 남긴다. 줄 양끝에 필요한 공백과 탭은 문자 참조로 쓴다. |
| 목록 | 글머리 기호와 번호 목록의 시작 번호·구분 기호를 유지한다. 이후 번호는 1씩 올린다. 들여쓰기는 4칸부터 시작하고 긴 번호는 기호 뒤까지 맞춘다. 같은 기호를 쓰는 목록 둘이 새로 붙으면 둘째 기호를 바꿔 두 목록을 유지한다. 작업 목록은 `[x]`와 `[ ]`로 쓴다. |
| 강조와 코드 | `*`, `_`, `**`, `__`와 코드 구분자의 표기를 유지한다. 편집한 내용과 구분자가 충돌하거나 밑줄 강조가 단어 속에 들어가면 구분자를 조정한다. 들여쓴 코드는 펜스로 바꾼다. 펜스 정보 앞뒤 공백을 정리한다. |
| 표 | 파이프를 열 구분자로 쓰고 셀 안의 파이프는 `\|`로 이스케이프한다. 열 정렬에 따라 `:---`, `:---:`, `---:`를 쓴다. 편집 중에 행의 열 수가 달라지면 빈 셀을 채우고 기존 내용은 보존한다. |
| 클래스 | 클래스 사이 공백을 한 칸으로 쓴다. 클래스가 있는 인용문이나 여러 블록을 감싼 컨테이너에는 클래스 전용 줄을 쓸 수 있다. 느슨한 목록에 항목 하나와 문단 하나만 있으면 문단과 클래스 전용 줄 사이에 빈 줄을 두어 목록 여백을 유지한다. `- - 항목`처럼 상위 항목의 기호 줄에서 시작한 목록이라 빈 줄을 두면 클래스 줄이 코드 블록이 될 때는 빈 줄 없이 써서 클래스를 지키고, 그 목록은 촘촘한 목록으로 다시 읽힌다. |
| 링크와 일반 문자 | 편집된 블록에서 참조 링크를 인라인 링크로 쓴다. 참조 정의는 별도 블록으로 남긴다. 일반 문자가 Markdown 구문으로 다시 읽히지 않도록 이스케이프를 추가할 수 있다. |
| 파일 경계 | 새 블록을 잇는 기본 구분은 빈 줄이다. 새 문서는 LF로 쓴다. 읽어 온 파일을 편집할 때는 그 파일의 첫 줄바꿈 형식을 새로 쓰는 부분에 사용한다. |

## 파이프라인 사용

- `src/editor/common/markdown/markdownIt.ts`의 `createMarkdownIt`는 순서가 있는
  플러그인 목록으로 토크나이저를 만든다.
- `parseMarkdown`은 ProseMirror 문서를 돌려준다. `parseMarkdownWithSource`는
  원문 모드와 커서 위치를 맞출 수 있도록 최상위 블록마다 ProseMirror 위치와 줄
  범위, UTF-16 오프셋을 돌려준다. 범위 끝은 배타적이다.
- `serializeMarkdown`은 원본에서 읽은 문서의 최상위 블록을 추적한다. 새 문서나
  ProseMirror JSON에서 만든 문서는 위 규칙으로 직렬화한다. 원문 보존은
  ProseMirror 트랜잭션을 거친 문서에도 적용된다.
- 등록된 플러그인이 스키마에 없는 토큰을 만들면 해당 최상위 블록을
  `raw_block`에 원문으로 보관한다. 이때 필요한 토큰의 `map`은 원문 줄 범위다.
  각주와 링크 정의는 참조되지 않아도 읽고 저장한다.
