# 마크다운 파일의 저장 형식

마크다운 원문은 파일에 그대로 저장된다. 편집 모델은 CommonMark 본문, GFM 표·작업
목록·취소선, 각주와 클래스 속성을 읽는다. 원시 HTML은 본문의 문자로 읽는다.

## 편집 모드와 실행 취소

- `.md`와 `.markdown`의 기본 모드는 WYSIWYG다. 같은 탭의 제목 툴바, **Markdown: Toggle Source Mode**, **Ctrl+Shift+M**(macOS는 **Cmd+Shift+M**)으로 원문 모드와 오간다. 기본 모드 설정과 저장 방법은 시작 가이드에 있다. [마크다운 편집하기](getting-started.md#마크다운-편집하기)
- 두 모드는 `TextFileEditorModel`을 공유한다. WYSIWYG의 문서 변경은 매 트랜잭션에서 직렬화하고 달라진 범위만 모델에 적용한다. 원문 탭이나 확장이 모델을 고치면 WYSIWYG도 새 텍스트를 읽는다.
- WYSIWYG는 이어서 입력한 글자를 500ms 간격으로 묶는다. 서식 명령과 외부에서 들어온 모델 변경은 각각 별도의 실행 취소 단계다. 키보드와 **Edit → Undo/Redo**가 같은 이력을 사용하며, 저장한 텍스트로 돌아오면 dirty 표시가 사라진다.
- 모드를 전환한 순간의 마크다운이 새 이력의 시작점이 된다. 그 뒤 첫 편집을 실행 취소하면 전환 순간의 텍스트로 돌아온다. 원문 모드로 전환할 때 같은 파일을 보여 주는 Monaco 창도 새 이력의 시작점을 공유한다. 새로고침은 탭 모드와 초안을 복원한다.
- 상대 경로 이미지는 WYSIWYG에서 대체 텍스트가 보이고, 저장할 때 원래 경로가 유지된다. 워크스페이스를 기준으로 한 이미지 표시는 wr-h2sa.kfw에서 다룬다.

## 클래스 속성

문단이나 제목을 꾸미려면 마지막 줄에 클래스 목록을 붙인다. 인용문과 목록 항목의
텍스트에 붙이면 인용문이나 항목에 적용된다. 표에서는 셀별로 붙인다. 글자 일부를
꾸미려면 대괄호 바로 뒤에 클래스 목록을 쓴다.

```markdown
# 제목 {.center}

부제목 {.subtitle}

> 인용 {.right}

- 항목 {.size-lg}

| 셀 {.center} |
| --- |

[글자 일부]{.size-lg .font-serif}
```

- 클래스 이름은 소문자로 시작하고 뒤에 소문자, 숫자, 하이픈을 쓸 수 있다. 여러
  클래스는 공백으로 나눈다. 사용자 클래스와 입력 순서가 저장된다.
- 줄 끝의 클래스 목록 앞에는 공백을 둔다. `글자{.class}`나 `![그림](a.png){.class}`처럼
  붙여 쓰면 글자로 읽는다.
- 클래스 목록만 있는 문단은 빈 줄 뒤에 있어도 바로 앞 블록(문단, 제목, 인용문, 목록,
  표, 코드 블록, 구분선, 각주)에 붙는다. 앞 블록이 없으면 글자로 남는다. 여러 블록을
  담은 인용문, 목록, 표, 코드 블록, 구분선은 이렇게 꾸민다. 클래스처럼 보이는 글자만
  있는 문단을 쓰려면 `\{`로 시작한다. 인용문이나 목록 항목 안의 문단만 꾸밀 때는
  같은 문단의 다음 줄에 `{.class}`를 쓰고 그 줄에도 인용 기호나 목록 들여쓰기를 넣는다.
  목록 항목 안에서 본문과 클래스 줄 사이를 한 줄 비워도 클래스는 문단에 붙으며,
  그 빈 줄은 목록 항목 사이를 비운 것과 같이 목록을 느슨하게 만든다.
- 목록 항목과 인용문 안의 클래스가 붙은 빈 문단은 `[]{.class}`로 쓴다.
  `- []{.class} {.item}`에서 `class`는 빈 문단에, `item`은 목록 항목에 붙는다.
  인용문에서는 `> []{.class}`를 한 문단으로 쓰고, 인용문 자체의 클래스는 인용문
  바깥의 클래스 전용 줄에 쓴다.
- 기존 문서의 `- []{.x}`와 `> []{.x}`도 클래스가 붙은 빈 문단으로 읽힌다.
  이 위치에서 `[]{.x}`를 글자로 쓰려면 `\[\]\{.x}`로 이스케이프한다.
  최상위의 `[]{.x}`는 글자로 읽힌다.
- 중괄호를 글자로 쓰려면 `\{`로 이스케이프한다. 코드 안의 중괄호와 링크·이미지의
  주소 및 제목은 해당 콘텐츠에 속한다. 이미지 설명은 평문으로 읽는다.

## 정규화 규칙

읽은 문서의 최상위 블록을 편집하지 않으면 원래 표기와 줄 끝을 그대로 저장한다.
편집 때문에 블록 경계가 바뀌면 빈 줄을 다시 쓸 수 있다. 링크 정의가 바뀌어 기존
링크가 다른 곳을 가리킬 수 있으면 기존 대상 URL을 인라인으로 저장한다.

| 다시 쓰는 부분 | 저장 표기 |
| --- | --- |
| 제목 | 한 줄 밑줄 제목은 `#` 또는 `##`로 쓴다. 여러 줄 밑줄 제목은 줄바꿈과 레벨을 유지하고, 마지막 텍스트 줄 아래에 `===` 또는 `---`를 쓴다. 제목 클래스는 마지막 텍스트 줄에 붙인다. |
| 줄바꿈과 공백 | 공백 두 칸으로 쓴 강제 줄바꿈은 줄 끝의 `\`로 쓴다. 본문의 일반 줄바꿈은 줄바꿈으로 남긴다. 줄 양끝에 필요한 공백과 탭은 문자 참조로 쓴다. |
| 목록 | 글머리 기호와 번호 목록의 시작 번호·구분 기호를 유지한다. 이후 번호는 1씩 올린다. 후속 줄은 해당 항목의 기호와 뒤 공백의 너비만큼 들여쓴다. 예를 들어 `- `는 두 칸, `9) `는 세 칸, `10) `는 네 칸이다. 중첩마다 이 들여쓰기를 더한다. 같은 기호를 쓰는 목록 둘이 새로 붙으면 둘째 기호를 바꿔 두 목록을 유지한다. 작업 목록은 `[x]`와 `[ ]`로 쓴다. |
| 강조와 코드 | `*`, `_`, `**`, `__`와 코드 구분자의 표기를 유지한다. 편집한 내용과 구분자가 충돌하거나 밑줄 강조가 단어 속에 들어가면 구분자를 조정한다. 들여쓴 코드는 펜스로 바꾼다. 펜스 정보 앞뒤 공백을 정리한다. |
| 표 | 파이프를 열 구분자로 쓰고 셀 안의 파이프는 `\|`로 이스케이프한다. 열 정렬에 따라 `:---`, `:---:`, `---:`를 쓴다. 편집 중에 행의 열 수가 달라지면 빈 셀을 채우고 기존 내용은 보존한다. |
| 클래스 | 클래스 사이 공백을 한 칸으로 쓴다. 클래스가 있는 인용문이나 여러 블록을 감싼 컨테이너에는 클래스 전용 줄을 쓸 수 있다. 목록 항목과 인용문 안의 클래스가 붙은 빈 문단은 `[]{.class}`로 쓴다. 느슨한 목록에 항목과 문단이 하나씩 있으면 문단과 클래스 전용 줄 사이에 빈 줄을 둔다. `- - 항목`처럼 상위 항목의 기호 줄에서 시작한 목록에도 적용한다. 이 문단이 비어 있으면 `[]{}`를 쓰고 한 줄을 비운 뒤 후속 줄의 들여쓰기로 클래스 전용 줄을 쓴다. |
| 링크와 일반 문자 | 편집된 블록에서 참조 링크를 인라인 링크로 쓴다. 참조 정의는 별도 블록으로 남긴다. 일반 문자가 Markdown 구문으로 다시 읽히지 않도록 이스케이프를 추가할 수 있다. |
| 파일 경계 | 새 블록을 잇는 기본 구분은 빈 줄이다. 새 문서는 LF로 쓴다. 읽어 온 파일을 편집할 때는 그 파일의 첫 줄바꿈 형식을 새로 쓰는 부분에 사용한다. |

### 목록 안의 블록 경계

- 촘촘한 목록의 문단 뒤에는 `#` 제목, 구분선, 표, 코드 펜스, 인용문을
  빈 줄 없이 잇는다. 인용문 뒤의 문단이나 표가 인용에 이어 읽힐 수 있으면
  빈 `>` 줄로 인용을 닫는다. 느슨한 목록의 블록 사이에는 빈 줄을 둔다.
- 촘촘한 항목에서 문단이나 클래스 전용 줄 뒤에 대시 구분선이 오면
  `- - -`처럼 대시 사이를 띄워 밑줄 제목과 구분한다. 항목의 첫 구분선이
  `- ---`나 `* ***`처럼 글머리 기호까지 구분선으로 읽히는 경우에는
  글머리 기호를 먼저 쓰고 구분선을 들여쓴 다음 줄에 둔다. 중첩된
  `-`나 `*` 기호만 모여 구분선으로 읽힐 때도 기호 줄을 나눈다.
- 중첩 목록 뒤 표, 별도 클래스 줄이 필요한 표, 클래스 전용 줄 뒤의 문단이나
  1 이외에서 시작하는 번호 목록에는 블록과 클래스의 소유권을 지키기 위해
  빈 줄을 둔다. 문단이나 클래스 줄 뒤에 오는 하위 목록이 기호만 있는 줄로
  시작할 때도 빈 줄을 둔다. 이 표기로 다시 열면 상위 목록이 느슨해질 수 있다.
- 여러 줄 밑줄 제목이 바로 앞 블록에 이어 읽힐 수 있으면 제목 앞에도 빈 줄을
  둔다. 제목과 이웃 블록이 각각 남도록 하는 구분이다.

## 파이프라인 사용

- `src/editor/common/markdown/markdownIt.ts`의 `createMarkdownIt`는 순서가 있는
  플러그인 목록으로 토크나이저를 만든다.
- `parseMarkdown`은 ProseMirror 문서를 돌려준다. `parseMarkdownWithSource`는
  원문 모드와 커서 위치를 맞출 수 있도록 최상위 블록마다 ProseMirror 위치와 줄
  범위, UTF-16 오프셋을 돌려준다. 범위 끝은 배타적이다.
- `serializeMarkdown`은 원본에서 읽은 문서의 최상위 블록을 추적한다. 새 문서나
  ProseMirror JSON에서 만든 문서는 위 규칙으로 직렬화한다. 원문 보존은
  ProseMirror 트랜잭션을 거친 문서에도 적용된다.
- 목록 직렬화는 `prosemirror-markdown` 1.13.4의 비공개 상태 `closed`,
  `inTightList`와 메서드 `flushClose`, `atBlank`에 의존한다. 버전을 올릴 때
  내부 동작을 확인하고 `src/editor/test/common/markdown/serializer.test.ts`를
  실행한다.
- 등록된 플러그인이 스키마에 없는 토큰을 만들면 해당 최상위 블록을
  `raw_block`에 원문으로 보관한다. 이때 필요한 토큰의 `map`은 원문 줄 범위다.
  각주와 링크 정의는 참조되지 않아도 읽고 저장한다.

### 저장 왕복 검사

기본 `npm test`는 조합에서 고른 고정 표본과 최소 재현을 검사한다. 목록
기호와 경계, 형제 항목, 중첩, 인용문, 각주가 포함된 전체 조합을 확인하려면
다음 명령을 실행한다.

```sh
MARKDOWN_ROUNDTRIP_FULL=1 npm test -- src/editor/test/common/markdown/roundtrip.property.test.ts --disableConsoleIntercept
```

테스트는 무편집 원문, 정규화, 텍스트 편집 저장, 클래스 편집 저장을 검사한다.
전체 실행은 검사한 입력 수와 저장 경로별 정규화 횟수를 출력한다.
들여쓴 코드의 펜스 표기와 클래스 경계를 지키기 위해 촘촘한 목록이 느슨해지는
경우만 모델 속성 차이로 허용한다. 문서 트리와 클래스 순서, 인라인 서식과
텍스트가 유지되는지 확인하고, 다시 정규화한 출력이 같은 표기로 계속 저장되는지
검사한다.
